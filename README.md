# SETU-STAT — AI Skill Intelligence & Learning Platform (SIH 26101)

AI-enabled learning platform for capacity building in India's Official Statistical System,
integrated with the iGOT Karmayogi ecosystem (replicated as a local "dummy iGOT" for the demo).

## What's inside

```
dummy-igot/       Frontend + dummy iGOT (static HTML/Tailwind, port 8090)
backend/          FastAPI app: auth, Sunbird-shaped catalogue, competency memory,
                  gap engine, roadmap recommender, transcript-grounded quiz
                  generation (gpt-5-mini via Azure OpenAI), Pinecone vector store
docs/             Solution blueprint + research/plan of action
```

## Key features

- **Dummy iGOT** replica: landing page, read-only registration (Dept. of Space & ISRO HQ demo user), Sunbird-shaped course catalogue (14 real iGOT courses)
- **25-question department-tailored assessment** (L1 easy / L2 medium / L3 hard)
- **Persistent competency memory** (`user_competency`, EWMA-merged from assessments, module quizzes, personalized quizzes, iGOT course completions)
- **Gap engine + personalized roadmap** — 5-course ISRO roadmap (IIRS/ISRO, NPTEL, NRSC, freeCodeCamp) with **on-site embedded YouTube players**, module-by-module lesson tracking
- **Transcript-grounded module quizzes** — 5 MCQs per module generated by gpt-5-mini strictly from the lecture YouTube transcripts (cached), graded into memory with strength/weakness
- **Trainer Studio** — priority mode: quiz generated from memory's weak areas + recommended course transcripts; upload mode: PDF/TXT → chunks embedded into Pinecone → retrieved chunks ground the MCQs
- **Org analytics** — competency distribution, completions, predictive capacity-building needs
- Welcome-popup flow gated on assessment status; "Later" opt-out

## Run it

```bash
# 1. backend deps (Python 3.12+)
pip install fastapi "uvicorn[standard]" httpx pypdf python-multipart pinecone youtube-transcript-api

# 2. configure keys (backend/.env — never commit)
OPENAI_API_KEY=...            # Azure OpenAI key
OPENAI_BASE_URL=https://<your-resource>.openai.azure.com/openai/v1
LLM_MODEL=gpt-5-mini
EMBEDDING_MODEL=text-embedding-3-small
PINECONE_API_KEY=...
PINECONE_INDEX=setu-stat

# 3. start backend (port 8001; 8000 is taken by unrelated apps on some machines)
cd backend && python3 -m uvicorn main:app --port 8001

# 4. start frontend
cd dummy-igot && python3 -m http.server 8090

# open http://localhost:8090  → Register (read-only demo user) → dashboard
```

Demo credentials: registration is one click (analyst@adrin.gov.in / demo123, auto-login).
The welcome popup + personalized roadmap unlock only after the 25-question assessment.

## Demo notes

- Demo DB: `backend/igot.db` (SQLite, auto-created; delete for a fresh start).
- Ports: frontend 8090, backend 8001 (8000 is commonly occupied).
- Keys live in `backend/.env` — never commit. Pinecone index auto-creates on first run.
- For judges: reset with `rm backend/igot.db`, register the ISRO user, take the assessment, and the whole loop runs live (no manual seeding needed).

## Deployment (Vercel frontend + Render backend)

The frontend resolves its API base automatically: `localhost` → `http://localhost:8001`,
any other hostname → `https://igot-karmayogi-api.onrender.com` (override by setting
`window.IGOT_API_BASE` before page scripts, e.g. in a small config snippet).

### Backend → Render
1. Render dashboard → New → Blueprint → point at this repo (`render.yaml` is at the root).
2. Fill in the `sync: false` env vars when prompted: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `PINECONE_API_KEY`.
3. Render builds with `requirements.txt`, starts `uvicorn main:app --host 0.0.0.0 --port $PORT`,
   and health-checks `/api/health`. Auto-deploys on every push to `main`.
   (If you use a different service name, update the fallback URL in `dummy-igot/common.js`.)

### Frontend → Vercel
1. Vercel → Add New Project → import the repo.
2. Set **Root Directory** to `dummy-igot` (framework preset: Other — it's static).
3. Deploy — `vercel.json` handles clean URLs + security headers. Auto-deploys on push to `main`.

### CI/CD
`.github/workflows/ci.yml` runs on every push/PR to `main`:
- **backend job** — installs `requirements.txt` on Python 3.12, imports the app (catches route/model
  definition errors), boots uvicorn and smoke-tests `/api/health` + catalogue search.
- **frontend job** — verifies every page uses the `IGOT_API_BASE` resolver (no hardcoded localhost),
  and all 9 pages exist.

### Production caveat (intentional for the demo)hi
Render's free tier has an **ephemeral disk** — `igot.db` (SQLite) resets on redeploy/restart, so the
demo user/assessment data lives only between restarts. For a persistent demo, attach a Render Disk
at `/opt/render/project/src/backend` or point `DB_PATH` at Postgres later.
